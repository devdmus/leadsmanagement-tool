# Quick Troubleshooting Checklist\n\n## ✅ If Dashboard Shows \"Error Loading Dashboard\"\n\n### Step 1: Check Browser Console (F12)\nOpen DevTools Console and look for error messages:\n\n**✅ Expected (working):**\n`\n🔍 [wpLeadsApi] Fetching from: http://localhost/mysite/wp-json/crm/v1\n✅ [wpLeadsApi] Fetched X leads from http://localhost/mysite/wp-json/crm/v1\n`\n\n**❌ Error 1: API_BASE is empty**\n`\n❌ [wpLeadsApi] API_BASE is empty. Site not configured or env variable not set.\n`\n→ **Fix:** Add a WordPress site in the \"Sites\" settings\n\n**❌ Error 2: API_KEY not configured**\n`\n❌ [wpLeadsApi] API_KEY (VITE_WP_API_KEY) is not configured.\n`\n→ **Fix:** Set `VITE_WP_API_KEY` in `.env` file\n\n**❌ Error 3: HTTP 401 Unauthorized**\n`\n❌ [wpLeadsApi] API Error 401: Invalid API Key\n`\n→ **Fix:** Check API key in `.env` matches WordPress plugin setting\n\n**❌ Error 4: HTTP 404 Not Found**\n`\n❌ [wpLeadsApi] API Error 404: Not Found\n`\n→ **Fix:** \n- Verify WordPress site URL is correct\n- Ensure WordPress plugin is activated\n- Check that `/wp-json/crm/v1/leads` endpoint exists\n\n---\n\n### Step 2: Verify Environment Configuration\n\n**Check `.env` file:**\n`bash\ncat .env\n`\n\nShould show:\n`\nVITE_API_BASE=/crm/v1\nVITE_WP_API_KEY=SECRET123\n`\n\n**Fix if different:**\n`bash\n# Edit .env file and set correct values:\nVITE_WP_API_KEY=<your-actual-api-key>\n`\n\nThen restart dev server:\n`bash\nnpm run dev\n`\n\n---\n\n### Step 3: Verify WordPress Site Configuration\n\n**In the app:**\n1. Click on \"Sites\" menu\n2. Check that at least 1 site is listed\n3. Verify the site URL matches your WordPress domain\n4. Make note of the exact URL\n\n**Example:**\n- ✅ `http://mysite.local/wordpress` - Correct\n- ✅ `https://example.com` - Correct\n- ❌ `http://localhost` - Wrong (should include WordPress path)\n\n---\n\n### Step 4: Verify WordPress Plugin\n\n**Check if plugin is active:**\n1. Go to WordPress admin\n2. Click \"Plugins\" → Search \"Activity Logs API\"\n3. Should show \"**Active**\" status\n\n**If not active:**\n1. Click \"Activate\"\n2. Return to the CRM app and refresh\n\n**Check API key in WordPress:**\n1. In WordPress functions.php or wp-activity-logs.php, look for:\n `php\n   define('CRM_API_KEY', 'SECRET123');\n   `\n2. This key must match your `.env` file `VITE_WP_API_KEY`\n\n---\n\n### Step 5: Test the API Directly\n\n**Using curl or Postman:**\n`bash\ncurl -X GET \\\n  'http://mysite.local/wordpress/wp-json/crm/v1/leads?api_key=SECRET123'\n`\n\n**Expected response:**\n`json\n[{\"id\": 1, \"name\": \"John\", \"email\": \"john@example.com\", ...}]\n`\n\n**If you get 404:**\n- Plugin not activated\n- Wrong URL\n- Plugin installation issue\n\n**If you get 401:**\n- Wrong API key\n\n---\n\n## ✅ If ChatWidget Shows No Data\n\n### Check Console Logs\n\n**Expected:**\n`\n👥 [ChatWidget] Loading users...\n✅ [ChatWidget] Users loaded: 8\n📝 [ChatWidget] Loading rooms...\n✅ [ChatWidget] Rooms loaded: 3\n`\n\n**If empty:**\n1. Check localStorage: `localStorage.getItem('crm_chat_rooms')` in console\n2. Create test data via API\n3. Refresh page\n\n---\n\n## 🔍 Debug Steps\n\n### Step 1: Check Network Requests (F12 → Network tab)\n1. Refresh page\n2. Look for requests to: `.../leads?api_key=...`\n3. Check response status:\n - ✅ 200 OK = Success\n - ❌ 401 = Wrong API key\n - ❌ 404 = Endpoint not found\n - ❌ 500 = Server error\n\n### Step 2: Check Local Storage\nIn browser console:\n`javascript\n// Check if sites were cached\nJSON.parse(localStorage.getItem('crm_wp_sites'))\n\n// Check current site ID\nlocalStorage.getItem('crm_current_site_id')\n\n// Check leads cache\nJSON.parse(localStorage.getItem('crm_leads_local_updates'))\n`\n\n### Step 3: Check Session Storage\n`javascript\n// Check profiles cache\nJSON.parse(sessionStorage.getItem('crm_profiles_cache'))\n`\n\n---\n\n## 📋 Verification Checklist\n\n- [ ] `.env` file has `VITE_WP_API_KEY` set\n- [ ] WordPress site configured in \"Sites\" menu\n- [ ] WordPress plugin \"Activity Logs API\" is activated\n- [ ] API key in WordPress matches `.env` value\n- [ ] Browser console shows green ✅ logs, not red ❌ errors\n- [ ] Network tab shows 200 OK responses\n- [ ] Dashboard loads stats without toast error notification\n- [ ] ChatWidget shows user list and chat rooms\n\n---\n\n## 🚀 After Fixing Issues\n\n1. **Refresh the page:** F5 or Cmd+R\n2. **Check console:** F12 and look for ✅ green logs\n3. **Verify in app:**\n - Stats appear on dashboard\n - Numbers match WordPress data\n - ChatWidget shows users\n - No red error toasts\n\n---\n\n## 📞 Still Having Issues?\n\n**Collect debug info:**\n`bash\n# 1. Copy console errors\n# 2. Check .env file\n# 3. Verify WordPress URL\n# 4. Run this in browser console:\nJSON.stringify({\n  api_base: document.querySelector('[data-api-base]')?.textContent,\n  env_key: document.querySelector('[data-api-key]')?.textContent,\n  plugins: JSON.parse(localStorage.getItem('wp_plugins') || 'null')\n}, null, 2)\n`\n\nProvide this information for faster debugging.\n
